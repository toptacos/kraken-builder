Kraken vs the alternatives — measured, not asserted

Kraken is a local-first CLI plugin runner: one JSON envelope on stdin, one on stdout, any language, no server. This page compares it with the tools people actually reach for, and puts the numbers on the table. Every benchmark below is produced by scripts in the repository, on a machine you can point at docs/BENCHMARKS.md for the method.

The short version

Smallest thing that works

0.4 MB of core, one dependency (pyyaml, MIT). The whole Homebrew install is 0.5 MB — measured, after trimming 16 MB of demo toolchains out of the package. No daemon, no server, no account.

Language-free contract

The same tentacle runs as .py, .sh, .js, .php, .rb, .pl, or .go — one manifest shape, no SDK. n8n wants TypeScript; Terraform wants Go.

Safe by default, off the network

Verified with the network cable cut. Exposure is default-deny and binds 127.0.0.1 until a human grants more. Nothing in a run calls home.

Composable without a plugin host

A hook is another tentacle: it returns a patch and core calls finish on the original tentacle with it. No event bus, no wrappers.

Where Kraken is outright wrong

Per-invoke speed is not the bet. A binary tentacle costs one interpreter start, so a trivial kraken run is an order of magnitude slower than a C binary like make. If your job is "run this one shell line," a Makefile is faster and smaller — use it. Kraken earns its keep when a line becomes a plugin someone else ships in another language, with a typed envelope, a grant, and no daemon.
