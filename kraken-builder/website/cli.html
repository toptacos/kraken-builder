CLI Playground

Try kraken commands in a secure, simulated environment. Every command runs inside a Docker container with --security-opt no-new-privileges, a read-only ~/.kraken/data mount, and no network access unless you explicitly opt in.

kraken@playground:~$ --version
kraken 0.4.2
kraken@playground:~$ help
usage: kraken [-h] [--root ROOT] [--version]
{init,list,doctor,monitor,run,queue,license,tentacle,workflow,serve-site,account,vanilla,demo,config,up,instance,grant,self,help}
...
kraken@playground:~$ help run
usage: kraken run [-h] [--payload PAYLOAD] [--compose] arm action
positional arguments:
arm
action
options:
-h, --help show this help message and exit
--payload PAYLOAD
--compose
--version help help run list doctor clear

Run your first command

kraken run echo echo --payload '{"ok":true}'

Output: {"echo": {"ok": true}}

List installed arms

kraken list

Shows every in-process arm with version, actions, kind, and license tier.

Check system health

kraken doctor

Verifies layout, protocol version, dependency plans, and install integrity.

Extend functionality — write a tentacle

Kraken is a plugin runner. A tentacle is a directory with a tentacle.yaml manifest and a handler.py (or any language handler). Core discovers it, resolves dependencies, and runs it in a sandboxed container.

# tentacle.yaml
name: hello
version: 1.0.0
actions:
  - name: greet
    handler: handler.py

# handler.py
import json, sys
name = json.loads(sys.argv[1] or '{}').get('name', 'world')
print(json.dumps({"ok": True, "message": f"Hello, {name}!"}))

Install and run it:

kraken tentacle add ./my-tentacle
kraken run hello greet --payload '{"name":"Alice"}'

Output: {"ok": true, "message": "Hello, Alice!"}

This playground simulates the CLI locally. No commands are sent to a server. For real Docker isolation, install kraken and run commands on your host — core shells out to Docker only for arms that declare needs_docker: true.
